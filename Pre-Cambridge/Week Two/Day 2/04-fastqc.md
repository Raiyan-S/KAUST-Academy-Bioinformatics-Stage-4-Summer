## 5.1 Assessing sequence quality with `FastQC`

The first step in any NGS pipeline is to **Quality Control (QC)** the “raw” data. For this, we use [FastQC](https://www.bioinformatics.babraham.ac.uk/projects/fastqc/), a standard tool that provides a modular set of quality control checks. FastQC acts like a “health check” for your reads, highlighting potential problems so you can choose the correct path forward: **trimming** or, in extreme cases, **resequencing**. Trimming is the process of using software (like `fastp`) to remove problematic parts of your reads while keeping the high-quality biological data intact. You choose this option when the core of your data is good, but the “edges” are messy. Resequencing involves going back to the original biological sample, re-preparing the library, or loading it onto a new flow cell to generate a fresh dataset.

NoteTypes of Illumina reads

There are two types of Illumina reads:

1. Single-End (SE) Reads
   * In single-end sequencing, the machine starts at one end of the DNA fragment and reads a set number of bases (e.g., 75bp or 100bp) in one direction. Once it reaches the end of that “read,” it stops. You get one FASTQ file per sample.
2. Paired-End (PE) Reads
   * In paired-end sequencing, the machine sequences one end of the fragment (Read 1), then flips the molecule and sequences the opposite end (Read 2). You get two sequences for every fragment (two FASTQ files, usually labeled \_R1 and \_R2 or \_1 and \_2). Even though there is an unsequenced “gap” in the middle of the fragment, the software knows exactly how far apart the two ends are.

Most of the time you will use paired-end reads, but if you start extracting samples sequenced a long time ago from public databases you may come across single-end reads so it’s good to have an understanding of what they are. In practice, most tools like `FastQC` and `fastp` work with both types of Illumina reads.

### 5.1.1 Basic FastQC command

`FastQC` is straightforward to run. You can provide a single file, or a list of files (such as R1 and R2 from paired-end sequencing).

```
# run on a single file (single-end Illumina, ONT, PacBio)
fastqc sample.fastq.gz

# run on two specific files
fastqc sample01_R1.fastq.gz sample01_R2.fastq.gz

# run on all fastq files in the directory
fastqc *.fastq.gz
```

By default, `FastQC` creates an HTML report and a ZIP file for every input file. The HTML report is what you will use to visualize the results.

## 5.2 QC assessment of NGS data

**QC** is an important part of any analysis and, in this section, we’re going to look at some of the metrics and graphs produced by `FastQC` that can be used to assess the quality of NGS data.

### 5.2.1 Base quality

[Illumina sequencing](https://en.wikipedia.org/wiki/Illumina_dye_sequencing) technology relies on sequencing by synthesis. One of the most common problems with this is dephasing. For each sequencing cycle, there is a possibility that the replication machinery slips and either incorporates more than one nucleotide or perhaps misses to incorporate one at all. The more cycles that are run (i.e. the longer the read length gets), the greater the accumulation of these types of errors gets. This leads to a heterogeneous population in the cluster, and a decreased signal purity, which in turn reduces the precision of the base calling. The figure below shows an example of this.

[![Base Quality](images/base_qual.png)](images/base_qual.png "Base Quality")

Base Quality

Because of dephasing, it is possible to have high-quality data at the beginning of the read but really low-quality data towards the end of the read. In those cases you can decide to trim off the low-quality reads. In this course, we’ll do this using the tool [fastp](https://www.ncbi.nlm.nih.gov/pubmed/30423086/). In addition to trimming and removing low quality reads, `fastp` will also be used to trim Illumina adapter/primer sequences.

The figures below show an example of high-quality read data (left) and poor quality read data (right). These graphs are generated by `FastQC` and show the average Phred score (a measure of quality) for each position in the reads. We’re looking for Phred scores > 30 and this is represented by the green zone in the graphs. We can see in the right hand graph that the quality of most of the reads fall within the yellow (quality > 20) and red zones (quality < 20). This is strong evidence that something went wrong during the processing of the DNA and/or sequencing.

### 5.2.2 Mismatches per cycle

Aligning reads to a high-quality reference genome can provide insights into the quality of a sequencing run by showing you the mismatches to the reference sequence. In particular, this can help you detect cycle-specific errors. Mismatches can occur due to two main causes: sequencing errors and differences between your sample and the reference genome; this is important to bear in mind when interpreting mismatch graphs. The figures below show an example of a good run and a bad one. In the first figure, the distribution of the number of mismatches is even between the cycles, which is what we would expect from a good run. However, in the second figure, two cycles stand out with a lot of mismatches compared to the other cycles.

### 5.2.3 GC bias

It is a good idea to compare the GC content of the reads against the expected distribution in a reference sequence. The GC content varies between species, so a shift in GC content like the one seen below (right image) could be an indication of sample contamination. In the left image below, we can see that the GC content of the sample is about the same as for the theoretical reference, at ~65%. However, in the right figure, the GC content of the sample shows two distributions: one is closer to 40% and the other closer to 65%, indicating that there is an issue with this sample, likely contamination.

## 5.3 Summary

TipKey Points

* `FastQC` generates a comprehensive HTML report summarizing several quality metrics.
* The Per base sequence quality plot is the most critical metric for identifying sequencing errors.
* Adapter Content warnings indicate that the sequencer read past the genomic DNA into the library preparation adapters.
* `FastQC` does not modify your data; it only reports on its status. Trimming tools like `fastp` are required to act on the findings.
